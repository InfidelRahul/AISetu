# AISetu

AISetu is a provider-independent AI conversation bridge. It translates canonical
conversations through provider adapters, and exposes an OpenAI-compatible local API.

```
OpenAI Request
      ↓
API
      ↓
Canonical Conversation
      ↓
Provider Adapter
      ↓
HTTP
      ↓
Provider
      ↓
Conversation
      ↓
OpenAI Response
```

## Build

Requires a stable Rust toolchain (1.75+).

```bash
cargo build
cargo test
cargo fmt
cargo clippy
```

Release profile (thin LTO, stripped):

```bash
cargo build --release -p aisetu
```

Cross-platform artifacts (Linux/Windows/macOS, x86_64 and ARM64) are produced
by `.github/workflows/ci.yml` and `scripts/build-release.sh`.

## Run

```bash
# Start the local API (127.0.0.1:8080 by default)
cargo run -p aisetu -- serve

# Inspect resolved configuration
cargo run -p aisetu -- config

# Capture a provider session via the browser plugin
cargo run -p aisetu -- login --provider mock --url https://example.com/login --cookie sid=abc
```

Optional configuration file: `config/aisetu.toml`, `./aisetu.toml`, or
`AISETU_CONFIG`. Environment overrides: `AISETU_BIND`, `AISETU_PORT`,
`AISETU_API_KEY`, `AISETU_LOG_LEVEL`, `AISETU_LOG_FORMAT`.

## API

- `GET /health`
- `GET /v1/models`
- `POST /v1/chat/completions` (including `stream: true`)

Default models:

- `aisetu-default` → mock provider
- `aisetu-echo` → echo provider

```bash
curl -s http://127.0.0.1:8080/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{"model":"aisetu-default","messages":[{"role":"user","content":"hello"}]}'
```

## Workspace

| Crate | Responsibility |
| --- | --- |
| `aisetu-core` | Errors, config, tracing, limits, redaction |
| `aisetu-transport` | Generic HTTP transport |
| `aisetu-conversation` | Canonical conversation model |
| `aisetu-engine` | Translation / extract / normalize / validate |
| `aisetu-intelligence` | IntelligenceEngine + deterministic extraction (not Cactus Needle 2) |
| `aisetu-provider` | Adapters, capabilities, routing, reliability |
| `aisetu-session` | Session lifecycle and secret storage |
| `aisetu-browser` | Replaceable authentication bridge |
| `aisetu-api` | HTTP API + OpenAI endpoints |
| `aisetu` | Binary, wiring, release entrypoint |

## Production status

This repository is a production-oriented Rust service, but “production ready” means the deployment-specific upstream contract and native runtime must also be verified. The included `openai_compatible` adapter supports upstreams that intentionally expose the documented OpenAI chat-completions contract. Provider-specific web/session adapters must only be implemented against permitted/documented interfaces.

### Upstream configuration

Use `kind = "openai_compatible"` for an OpenAI-compatible gateway. The base URL should point at the upstream `/v1` API root; AISetu appends `/chat/completions`. An API key can be supplied through `AISETU_PROVIDER_<PROVIDER_NAME>_API_KEY`. Session cookies/headers captured for the same provider are also applied.

### Streaming

The API emits OpenAI-compatible SSE. Providers that implement native streaming should override `Provider::stream`; providers without native streaming use a safe single-delta fallback rather than fabricating fixed-size chunks.

### Needle / Cactus

The repository deliberately does not ship a fake Needle implementation. `aisetu-intelligence` currently provides deterministic extraction and an abstraction boundary for a real Cactus/Needle backend. Integrating the actual native Cactus Engine requires its licensed/selected native artifacts and target toolchain; those artifacts are deployment inputs and are not generated by this source archive.

### Release verification

Before deploying, run:

```text
cargo fmt --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-targets
cargo audit
```

Then perform an end-to-end test against the actual configured upstream, including authentication, normal completion, SSE, timeout, rate-limit handling, session expiry, and restart/recovery.
